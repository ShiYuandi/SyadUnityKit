# Input 与 UDP 模板创建工具详解

SYAD Unity Kit 的模板创建工具会把可修改的项目脚本生成到当前项目 `Assets`，并自动创建场景对象。它适合第一次接入 InputRouter 或 UDP 接收器时使用。

生成出来的脚本属于你的项目，不属于只读的 UPM 包。以后可以直接修改、改名或删除。

该工具自 `0.4.0` 起正式提供。

## 一、创建 Input 系统

先保存当前场景，然后执行：

```text
Tools > SYAD Unity Kit > Input > 创建输入系统模板
```

工具会生成：

```text
Assets/SyadUnityKit/Generated/Input/
├─ SyadInputCommand.cs
├─ SyadInputSource.cs
├─ KeyboardInputSource.cs
├─ UdpInputSource.cs
└─ SyadInputController.cs
```

Unity 编译完成后，工具会在原场景自动创建：

```text
SYAD Input System
├─ KeyboardInputSource
└─ SyadInputController
```

这里显示的是同一个 GameObject 上的两个组件。

默认按键是：

- 左方向键：`Left`；
- 右方向键：`Right`；
- 空格键：`Confirm`。

进入 Play Mode 后按下这些键，就会经过：

```text
KeyboardInputSource
→ SyadInputController.SubmitCommand
→ InputRouter.TryDispatch
→ SyadInputController.HandleCommand
```

通常只需要修改两个地方：

1. 在 `SyadInputCommand.cs` 中定义项目真正使用的命令；
2. 在 `SyadInputController.HandleCommand` 中编写命令通过后的业务。

需要改变键位时，修改 `KeyboardInputSource.Update`。输入源只负责发现命令，不处理冷却和业务。

## 二、为什么使用输入源基类

各脚本的职责不同：

```text
SyadInputCommand
    定义项目能理解哪些离散命令

InputSource<TCommand>
    UPM Runtime 中的通用输入源基类，提供事件和 RaiseCommand

SyadInputSource : InputSource<SyadInputCommand>
    项目侧桥接类，只负责指定项目命令类型

KeyboardInputSource : SyadInputSource
    把键盘按键转换成命令

UdpInputSource : SyadInputSource
    把 Left、Right、Confirm 等 UDP 文本转换成命令

SyadInputController
    订阅输入源数组，把命令交给 InputRouter
```

`SyadInputController` 不再分别保存键盘、UDP、RFID 等字段，而是保存：

```csharp
SyadInputSource[] _inputSources
```

`InputSource<TCommand>` 属于框架 Runtime，因此不依赖任何项目枚举。生成到 `Assets` 的 `SyadInputSource` 是非泛型桥接类，让 Unity 2019.4 的 Inspector 可以继续配置 `SyadInputSource[]`。

以后新增 RFID 或触摸输入时，仍然只需继承项目侧 `SyadInputSource` 并放入数组，不需要直接继承泛型基类，也不需要修改 `SyadInputController` 或 `InputRouter<TCommand>`。

## 三、创建 UDP 接收器

先保存当前场景，然后执行：

```text
Tools > SYAD Unity Kit > Networking > 创建 UDP 接收器
```

工具会生成：

```text
Assets/SyadUnityKit/Generated/Networking/
└─ SyadUdpReceiverController.cs
```

Unity 编译完成后，工具会创建：

```text
SYAD UDP Receiver
├─ UdpReceiverBehaviour
└─ SyadUdpReceiverController
```

如果当前场景已经创建 Input 系统，工具还会把 `UdpInputSource` 添加到 UDP 对象，并把键盘和 UDP 输入源自动写入 `SyadInputController` 的输入源数组。先创建 UDP、后创建 Input 也能得到相同结果。

默认监听 `0.0.0.0:15000`。项目收到一个完整 UTF-8 UDP 数据包后，会进入：

```csharp
SyadUdpReceiverController.HandleMessage(string message)
```

在这个方法中解析国家名称、温度、距离、压力或项目自己的文本协议。

## 四、把 UDP 转换成 Input 命令

UDP 和 Input 默认保持独立。只有项目确实需要时，才把 UDP 文本转换成离散命令：

```text
UdpReceiverBehaviour
→ UdpInputSource
→ InputSource<SyadInputCommand>.CommandDetected
→ SyadInputController
→ InputRouter.TryDispatch
```

默认 `UdpInputSource` 会忽略大小写和首尾空格，把 `Left`、`Right`、`Confirm` 映射为对应命令。项目可以直接修改它的映射规则。

`SyadUdpReceiverController` 不再充当输入源，它只处理温度、距离、压力、分贝和 JSON 等普通 UDP 业务数据。这样通用 UDP 处理不会依赖 `SyadInputCommand`。

## 五、重复执行菜单

工具采用保守规则：

- 已存在的生成脚本不会被覆盖；
- 已存在对应控制器的场景对象不会重复创建；
- 对象缺少组件时会尝试补齐；
- Input 和 UDP 菜单可以按任意顺序执行，并自动连接已经存在的输入源；
- 新创建的对象可以通过 Unity Undo 撤销；
- `Assets/Demo` 和 UPM Runtime 源码不会被修改。

因此，修改生成脚本后可以再次执行菜单，不会丢失已有代码。

## 六、常见问题

### 菜单提示先保存场景

脚本生成后 Unity 会编译并重新加载代码。工具必须记住对象应该创建到哪个场景，因此要求先保存场景。

### 脚本已生成，但没有创建对象

先查看 Console 是否存在编译错误。工具只有在生成脚本成功编译后才能识别并挂载组件。修正编译错误后，Unity 重新编译时会再次尝试完成创建。

### 我可以改生成目录吗

创建完成后可以在 Unity Project 窗口中移动脚本。脚本已经属于项目，运行时不依赖最初的文件路径。

### Inspector 和代码订阅可以同时使用吗

`SyadUdpReceiverController` 默认通过代码订阅 UDP 事件。不要再把同一个处理方法重复绑定到 Inspector，否则一条消息可能被处理两次。若希望完全使用 Inspector，请删除模板里的代码订阅和退订。
